OtterDesk organizes work around a supervision loop: **mission → co-worker → evidence → decision → trust**.

## Co-worker, run, and schedule

| Concept | What it means |
| --- | --- |
| Co-worker | A hired role with its own mission, saved setup, conversation, and runtime work. |
| Blueprint | The catalog definition you inspect and hire. Requirements and capabilities come from this definition. |
| Run | One execution of a co-worker's work. A batch co-worker can have many runs; a live service can keep one run active. |
| Schedule or shift | Saved timing for automatic work. Pausing a run and pausing its future schedule are separate controls. |
| Evidence | The source material, report, observations, or outputs supporting a result. Availability depends on the co-worker. |
| Requested input | A question or review that requires your response through a declared control. |

Opening an existing co-worker does not start a new run. Completing first-time Chat setup can start one. Read [Setup and configuration](/docs/setup) before supplying the last answer.

## What status tells you

| Label | How to interpret it |
| --- | --- |
| Ready | No work is currently active; check required setup before starting. |
| Running | Work is active. For a live co-worker, this can mean an ongoing service rather than a task nearing completion. |
| Scheduled | Future work is planned. A queued run can also say **Waiting for resources**. |
| Paused | Current work has been paused. Its schedule may still need separate attention. |
| Needs review | Open the co-worker to inspect a pending request, result, or failure. |

Detailed views may also show preparation, completion, failure, cancellation, or unavailable status. A badge is a starting point; inspect the latest activity and its timestamp before acting.

## Trust is specific to the work

Check the inputs, connected services, limitations, and evidence. A successful run means the workflow completed; it does not certify the quality of its conclusions. Human approvals apply to the particular request shown, and a report's display controls do not grant approval.

Use [Run controls](/docs/run-and-pause), [Review work](/docs/review-work), and [Approvals](/docs/approvals) for the day-to-day actions.
