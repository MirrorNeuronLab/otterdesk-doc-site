# Availability and recovery

OtterDesk is designed to make temporary problems clear and recoverable. When something is not available, start by reading the current status and taking the next safe action it presents.

## A co-worker cannot start

Check whether it is configured, whether the runtime is healthy, and whether its resource requirements are met. Then retry **Test now**.

## A schedule did not run

Open **Shifts**, refresh the schedule state, and check whether the schedule is enabled. Review any scheduler message, then check runtime health before changing timing.

## A connected PC is unavailable

Use **Settings → Resources** to check available capacity. If the computer will be offline for a while, remove it from the cluster and avoid scheduling work that depends on its capacity.

## A run was interrupted

Open the co-worker, review the latest activity, and decide whether to pause, correct configuration, or start a fresh test. Avoid assuming an interrupted run produced a complete result.
