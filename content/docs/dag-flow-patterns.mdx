# Work progress and steps

When a co-worker is working, OtterDesk can show its public progress steps in a list or graph view. Both views describe the same work; choose the one that makes the current state clearest to you.

## Use the list view for quick checks

The list is best when you want to see what has finished, what is active, and what still needs attention. Start here during a short test or routine review.

## Use the graph view for relationships

The graph is useful when you want to see how steps relate to one another. It can help explain why a later step is waiting or where a run stopped.

## When a step needs attention

Open the co-worker's activity and evidence around that step. If the co-worker asks for input, use its **Decision needed** card. If the run failed, review the message, check [Runtime health](/docs/runtime-architecture), and retry only after correcting the relevant issue.

Step labels are about the co-worker's work, not a promise that every detail is complete. Review its final output and evidence before you act on an important result.
