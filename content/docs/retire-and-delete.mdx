---
title: Retire, restore, or delete a co-worker
description: Archive a role while preserving history, restore it later, or confirm permanent deletion.
---

Choose the action that matches what you want to retain. Pausing work, archiving a co-worker, and deleting its runtime data have different effects.

## Archive a co-worker

Open its details and use **More actions → Archive**. Review the confirmation before proceeding. The action can be described as retiring a co-worker in the surrounding workflow.

Archiving removes the hire from the active team while keeping its configuration, Chat history, and retained runtime knowledge and records available for review. Check that current work and automatic schedules have been stopped or paused as intended.

## Inspect or restore the archive

Open **Settings → Archived**. Select the available history or conversation action to inspect the old hire. Choose **Restore** to return it to My Team with retained data and history.

Restoration leaves work stopped and schedules paused. If the same blueprint already has a current hire, archive that hire first. A newly hired replacement has its own fresh Chat and setup; the retired hire's history stays with the retired hire.

## Permanently delete

From Archived, use the permanent delete action only after checking the information it will remove. Complete the explicit confirmation. This removes the archived hire's retained runtime job data and associated desktop records; it is not merely hiding a card.

Save a [backup ZIP](/docs/backup-and-restore) first if you need a portable runtime record. Files you supplied from external folders and copies you exported have their own storage ownership; do not assume permanent deletion is a whole-computer secure erase.

## Exports and transfers

**Export ZIP** in a co-worker's details is a package export. **Save backup ZIP** in Settings is the runtime data/dependency transfer workflow. Use the latter when you need to restore a saved co-worker on another compatible installation.
