title: Chat with a co-worker
description: Use contextual Chat for questions, setup, requested input, and supervised run controls.
---

Select a co-worker in the sidebar or its card header in My Team. Chat belongs to that hired co-worker, with its saved history and available work context.

## Message and Respond

The bottom input area has two purposes:

| Mode | Use it for |
| --- | --- |
| **Message** | Ask a question or write a normal follow-up. Enter sends; Shift+Enter inserts a line break. |
| **Respond** | Answer the selected setup question, approval, choice, rule review, or other requested action. |

A single choice or setup input source submits when selected. Text responses, multi-field forms, and multiple selections keep an explicit submit action. Optional notes and less-used controls may be collapsed. If several requests are pending, select the one you intend to answer.

Drafts for different input modes are kept separately for the app session. Selecting a suggested prompt fills a draft; it does not send it. Credentials use dedicated secure controls.

## Ask a focused question

Try “What are you responsible for?”, “Which evidence supports this result?”, or “What are the limitations of this report?” A co-worker with verified knowledge access can use its available work context. Desktop guidance can also be available before that connection is ready.

Read the readiness message. Guidance with limited work context cannot verify current work. While a run is busy, ordinary questions can receive a short request to ask again after the run finishes; do not assume the question was queued for an automatic answer.

## Start and pause through Chat

An explicit Chat request to start or resume opens a confirmation for the selected co-worker. Confirm it or give a concise affirmative while it is valid; confirmations expire after five minutes. Pause requests use the current co-worker's run controls directly.

Initial guided setup has its own save-and-start flow. See [Setup](/docs/setup) for the final-answer behavior, and [Run controls](/docs/run-and-pause) for later starts and recovery.

## Find history and inspect reports

Use **Search conversation** to find messages. Matching report details and folded observations can open so the result is visible. Copying a co-worker message preserves its saved content; transient live activity is not a saved message.

Reports can offer **Discuss findings**, **Discuss next step**, or similar actions. These prepare a follow-up draft. Review and send it yourself. Discussion and opening a report do not approve runtime work.

## Help, memory, and clearing Chat

The co-worker may offer help with setup, failures, results, or schedules. Accepting help begins the guided task; saving a schedule or retrying a failed run still requires its explicit review action. **Dismiss**, **Cancel**, or **Done** stops further unsolicited suggestions for that hire; you can ask for help later.

Use **Memory** in the workspace panel for supported saved instructions. **Clear chat** asks for confirmation and clears conversation history; it does not restart setup or erase runtime work, configuration, and domain knowledge. See [Memory and files](/docs/memory-and-files).
